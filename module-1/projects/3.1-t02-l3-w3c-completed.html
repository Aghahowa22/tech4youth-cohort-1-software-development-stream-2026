What is Web Accessibility?

Web accessibility means making websites usable by everyone, including people with disabilities. This includes people who are blind, deaf, colorblind, or have motor disabilities. But accessibility isn't just for people with permanent disabilities— it helps everyone in temporary situations too.

Accessibility benefits everyone. Think about these situations:

  • Captions on videos help in loud environments and help people learn new languages
  • Keyboard shortcuts speed up experienced users, whether they use a mouse or not
  • Large text options help not just people with vision loss, but anyone in bright sunlight
  • Clear instructions help all users, but are essential for people with cognitive disabilities
  • Alternative text for images helps when images don't load and helps search engines understand your content
Key Principle: Accessibility is inclusive design. When you build for people with disabilities, you create better experiences for everyone.

WCAG 2.1 Guidelines

The Web Content Accessibility Guidelines (WCAG) are the international standard for web accessibility. They're created by the W3C and used by governments and organizations worldwide. WCAG 2.1 is the current standard (released in 2018).

The POUR Principles

WCAG is organized into four core principles, remembered by the acronym POUR:

Perceptible — Information must be perceivable to at least one sense

Users must be able to see, hear, or otherwise perceive content. This means images need alt text, videos need captions, and text must be readable (not too light or too small).

Operable — Interface must be operable via keyboard and other input methods

Users must be able to navigate and use all interactive elements. This means every link and button must be reachable via keyboard (Tab key), with visible focus indicators.

Understandable — Content and interface must be clear and predictable

Users must understand what content means and how to use the interface. Text should be clear, instructions should be obvious, and the site should behave predictably.

Robust — Content must work with all browsers and assistive technologies

Your code must be valid HTML and CSS. It must work with screen readers, voice control, and other assistive technologies. Use semantic HTML and ARIA where appropriate.

Conformance Levels

  • Level A (Minimum): Basic accessibility requirements. Rarely sufficient.
  • Level AA (Standard): The industry standard. Most organizations aim for this.
  • Level AAA (Enhanced): Highest level of accessibility. Not always practical for all content.

This project and course aim for WCAG 2.1 Level AA compliance.

What Makes This Form Accessible?

  • Labels: Every input has a <label> with a for attribute
  • Required indication: Required fields marked with asterisk and aria-required
  • Helper text: Descriptive hints linked with aria-describedby
  • Keyboard navigation: Tab through fields in logical order
  • Focus indicators: Visible outline when focused (try tabbing!)
  • Checkbox labels: Properly associated so label is clickable
  • Button: Clear text describing action

Accessibility Resources & Tools

Automated Testing Tools

  • axe DevTools — Browser extension for checking accessibility issues
  • Google Lighthouse — Built into Chrome DevTools; audits accessibility, performance, and more
  • WebAIM WAVE — Browser extension and web service for accessibility evaluation
  • WebAIM Color Contrast Checker — Verify text has sufficient contrast

Screen Readers (Manual Testing)

  • NVDA (Free) — Open-source screen reader for Windows. Download here
  • JAWS (Paid) — Professional screen reader for Windows. Trial available at Freedom Scientific
  • VoiceOver (Built-in) — Mac and iOS. Press Cmd+F5 to enable.
  • TalkBack (Built-in) — Android screen reader. Built into all Android devices.

Documentation & Learning

  • WCAG 2.1 Quick Reference — Official WCAG guidelines with examples
  • WebAIM — Comprehensive accessibility education and resources
  • ARIA Authoring Practices — How to use ARIA for dynamic content
  • A11ycasts by Google Chrome — Short video series on accessibility topics
Pro Tip: The best way to understand accessibility is to test with real users who use assistive technologies. If possible, work with accessibility consultants or hire user testers who have disabilities.
